文档中心从「类目契约的示例」做成「真能查文档的应用」。上一轮（D2′）它只证明了 embed 类目渲染得出来，本轮把它身上四处实测出来的坏补掉，并把被门禁放过一次的口径失真一并修正。

- **深链不再套壳**：`vite.config.ts` 加内联插件 `serve-embedded-docs`，对 `/docs/` 前缀依次试 `<path>.html`、`<path>/index.html`，**命中真实文件才重写 `req.url`** 再交回 Vite 的静态服务（响应头与缓存不改），dev 查 `public/docs`、`configurePreviewServer` 查 `dist/docs`。此前 `/docs/`、`/docs/components/`、`/docs/tokens` 这类目录根与无扩展名深链在 dev/preview 两侧**全部**落回 WebOS 自己的壳 HTML：Vite 服务 `public/`/`dist/` 的 sirv 配了 `extensions: []`，`htmlFallbackMiddleware` 又只看项目根，而文档站开着 `cleanUrls`、站内链接本来就全是这两种形态（改 `cleanUrls: false` 也救不了 logo 的 `normalizeLink('/')` 与带尾斜杠的 nav）。同源入口的口径因此在文档里从「必须带扩展名」放宽为**三层各管一段**。
- **首开即有内容**：`predev` 挂 `node scripts/embed-docs.mjs --if-missing`（已有产物就跳过，缺时才实跑，约 1.5s），Playwright 的 webServer 走同一条 `npm run dev`，于是没挂 `pretest:e2e` 的 `test:e2e:a11y` / `test:e2e:visual` 两个 job 也一并自愈——npm 的 `pre<script>` 只对同名 script 生效，这是它们此前撞上「iframe 里只有一行裸文本」的原因。
- **文档站会「查文档」**：开 `themeConfig.search = { provider: 'local' }` 并配 `options.translations`（VitePress 不自带搜索，而默认件文案是英文，中文站只开 provider 会显示 "Search"）；激活根级 `lastUpdated`（只配 `themeConfig.lastUpdated` 是改文案不是启功能）；补 `/tokens` 与 `/architecture` 的参考侧栏。搜索索引与 `minisearch`/`mark.js`/`focus-trap` 全是 VitePress 自带依赖、只落 `dist/docs`（实测新增 2 个懒加载 chunk ≈201KB），OS 首屏与单块预算都不受影响（纯检出实测 235.5KB / 预算 700KB）。⌘K 与 `/` 的归属同时写进指南：焦点进了 frame 之后开的是文档站内搜索，**不**由父层接管 frame 快捷键——那等于给 embed 类目开同源专属特权，违反「chrome 对类目一无所知」。
- **被嵌入的实例从此零副作用**：反嵌套判定从 `main.ts` 的启动链尾上移到新的 `src/entry.ts`（`index.html` 的模块脚本改指它），判定通过才 `void import('./main')`。旧形态里被嵌的那份文档照样跑完 `theme.restore / vfs.init / webApps.restore / wm.restoreLayout` 才早退，而 `wm.$subscribe → schedulePersist` 的 400ms 防抖会把内层刚恢复出的旧快照写回**同一份** `layout-v1`，盖掉外层这期间的布局改动——「不挂载」挡不住，只有「不启动」挡得住。降级页按成因分两态：`/docs/` 前缀 → `docs-fallback`（处方 `npm run docs:embed`），其余 → `self-embed`（处方「同源入口要写成真实文件地址」），混进一句话等于把「能修」和「你用错了」揉在一起；双语用并列 `<p lang="zh-CN">`/`<p lang="en">`（此刻 i18n 还没启动），样式是 `main.css` 里新增的 `.embed-guard*` + 既有 token，恒浅色（它不读 `theme-v1`，一张说明页不值得引入状态依赖）。代价写在代码注释里：顶层首屏多一跳往返，`scripts/check-bundle.mjs` 的首屏口径因此从 `index+vue+vendor` 改为 `index+main+vue+vendor`（`git worktree` 纯检出实测：入口 4.2 + 壳层 `main` 77.7 + `vue` 147.7 + `vendor` 8.3 = 237.9KB，比拆分前同一口径的 235.5KB 多 2.4KB，即入口块与动态导入包装本身——漏算 `main` 等于凭空少掉整个壳层。）**这一组数字是重测的**：先前写在文档里的 243.5 / 249.6 / 89.3 出自共享工作区，那棵树同时带着另一条线未提交的壳层改动，`main` 块因此虚高 11.6KB；包体读数一律以干净检出为准，本轮把入口拆成 `entry.ts` 后 `main` 是否算进首屏也只剩这一种量法。。
- **口径与命名**：`website/index.md` 与 `website/architecture.md` 的组件数 18 → 41（`src/ui/Os*.vue` 实测；《WebOS对标AntDesign迭代规划》§3 的 18 与 31 是规划时点快照，不回改，只在注尾加指针）；`en-US` 的 `apps.docEditor` 由 `'Docs'` 改为 `'Doc Editor'`，让位给无宾语的「文档」`docsCenter`——英文界面上两个应用同名是用户能直接看到的错。
- **门禁**：`tests/e2e/docs-deep-link.spec.ts` 9 条（首开 `.VPHome` 在场 + 内链三形态盘点 + 搜索触发件装配 + 三条硬导航各锁 `html[data-webos-guard]` 计数 0 + 守卫两态各自的处方文案与「卡片有边框」这条反裸文本断言 + 一条被嵌实例零副作用），`tests/unit/embed-guard.test.ts` 8 例（成因判别含「`/docsx` 不算文档站」、两态处方互斥、挂载残留被清），`tests/unit/i18n.test.ts` 新增「同一语言内 `apps.*` 取值不得重复」——key 齐平门禁管「有没有」，管不到撞名这一类。零副作用那条是实测改出来的：原设计断「刷新后少没少窗口」，实测发现（a）全新上下文里 `layout-v1` 为空，内层 `restoreLayout` 原样早退、一次都不写，那样的绿是假的，故用例先开一扇窗并等 700ms 落一次非空布局作前置；（b）内外各持一个 400ms 防抖，谁后落盘取决于模块图加载耗时，是时序竞赛不是不变量——于是改成用 `page.addInitScript` 给每个文档的 `IDBObjectStore.prototype.put` 记账、断言内层对 `layout-v1` 零写入。反证四跑四红：摘中间件 → 三条硬导航红；把守卫挪回 `.then()` 链尾 → 零副作用红（实测 `Received: 1`）；摘 `search.provider` → 触发件断言红；把 `docEditor` 改回 `'Docs'` → 撞名用例红并报出两个 key。
